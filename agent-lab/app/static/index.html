Build on earlier jobs (optional)

The new job gets a copy of each chosen job's workspace in ./prior/<job-id>/, with a summary of how it went. The original jobs are never changed.

Drag nodes to move them. Drag from a node's right-hand dot to another node to connect them, using the edge type picked above. Click a node or edge to edit it. Click empty space to edit the lab-wide instructions.

Change Agent Lab itself

Describe a change to this app: a new feature, a different layout, a fix. One assistant edits a copy of Agent Lab's source code. When it finishes, Agent Lab checks the new code (it must compile, start, and keep the sandbox settings), applies it, and restarts, waiting first until no job is running. It then pushes the change to GitHub if you leave that ticked. You can undo the latest change.

Notifications (ntfy)

Install the ntfy app on your phone and subscribe to a hard-to-guess topic name. Anyone who knows the topic on ntfy.sh can read it.

Permission requests always send a notification.

Defaults

GitHub (for the Modify app tab)

After a change made in the Modify app tab is applied, Agent Lab can push it to your GitHub repository. It uses git on this Mac. If git isn't signed in to GitHub here, paste a fine-grained token with Contents: read and write on just that repository. The token stays in Agent Lab's settings on this Mac, and agents can't read it.

Sandbox self-test

Starts a short Claude Code session that tries to read your home folder, list ~/Documents, write outside the lab, write inside it, and reach the internet. Then it repeats the risky checks through the GPU launcher, and checks that the GPU is visible through it. Everything outside the lab should be blocked; internet and GPU should work.

Agent Lab server

Agent Lab runs in the background: the Terminal window that starts it closes itself. Stop it here, and open the Agent Lab icon to start it again. Its output goes to agent-lab/runtime/server.log.
